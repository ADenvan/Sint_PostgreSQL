
- [[Агрегаты с GROUP BY - итог по каждой группе]] - Но чаще в отчётах нужно получить не один общий итог, а итоги по группам. `GROUP BY category` означает: «разбей строки на группы по категории и посчитай агрегаты отдельно для каждой группы».
- [[Как читать запрос с агрегатами и GROUP BY]] - То есть результат будет не «одна строка на заказ», а «одна строка на клиента».
- [[Почему нельзя просто написать колонку рядом с агрегатом]] - Проблема в том, что `COUNT(*)` хочет вернуть один итог по всей таблице. 
	- SQL не может угадать, какой именно `customer_id` показать рядом с общим количеством заказов.
	- Если в `SELECT` есть агрегатные функции и обычные колонки, то обычные колонки должны быть в `GROUP BY`.
- [[Агрегаты с DISTINCT]] - `DISTINCT` можно использовать не только с `COUNT`.
- [[Как агрегаты работают с NULL]] - `NULL` — одна из главных причин неожиданных результатов в агрегатах.
	- Самая частая практическая защита — `COALESCE`.
- [[Писать обычную колонку рядом с агрегатом без GROUP BY]] - Если хочешь получить количество пользователей по каждому имени, нужен `GROUP BY name`.
- [[Забывать, что AVG пропускает NULL]] - Если у товара две оценки: 5 и `NULL`, средняя будет 5, а не 2.5.
	- Потому что `NULL` не считается нулём.
- [[Использовать MIN и MAX по тексту там, где нужны числа]] - Для строк значения сравниваются как текст. Поэтому для числовых сравнений лучше хранить данные в числовом формате или заранее приводить типы, если это безопасно.
