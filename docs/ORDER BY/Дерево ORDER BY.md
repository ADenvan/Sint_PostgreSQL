
# Что такое ORDER BY в SQL?

`ORDER BY` — команда для сортировки результата в `SQL`. Простыми словами: `ASC` и `DESC`, сортировка по нескольким колонкам, `NULL`-ы в сортировке, комбо с `LIMIT` для топ-`N`. Куча примеров и три задачи на потренироваться.

---
## Зачем нужен ORDER BY

Сортировка нужна почти в любом реальном приложении.

Без неё неудобно смотреть списки, строить рейтинги, выводить историю действий, показывать товары, новости, заказы и отчёты.

Типичные ситуации:

- показать товары от дешёвых к дорогим;
- вывести последние новости сверху;
- собрать топ пользователей по очкам;
- отсортировать города по алфавиту;
- показать заказы от новых к старым;
- найти самые крупные платежи;
- построить лидерборд.

---
[[ORDER BY]] - `ORDER BY` — это часть SQL-запроса, которая отвечает за сортировку результата.
- [[ASC и DESC]] - Тип данных (Числа - Даты - Строки)
	- `ASC` — по возрастанию;
	- `DESC` — по убыванию.
- [[ORDER BY по нескольким колонкам]] - Например, мы хотим отсортировать сотрудников сначала по отделу, а внутри каждого отдела — по зарплате от большей к меньшей.
	- [[Почему важна стабильная сортировка]] - Особенно это важно при связке `ORDER BY` и `LIMIT`.
- [[ORDER BY и LIMIT]] - `ORDER BY` сначала расставляет строки в нужном порядке, а `LIMIT` берёт только первые.
	- [[Пример - последние заказы]] - Допустим, нужно показать 5 последних заказов.
	- [[Сортировка по выражению]] - В `ORDER BY` можно указывать не только готовые колонки, но и выражения.
		- `LENGTH(name)` - Ещё пример — сортировка по длине имени
	- [[Сортировка по вычисляемой колонке]] - Часто выражение удобно вывести в `SELECT`, дать ему понятное имя и потом сортировать по этому имени.
	- [[Сортировка через CASE]] - `CASE` здесь превращает статусы в условные числа для сортировки: Так мы сортируем не по алфавиту, а по смыслу.
	- [[NULL в сортировке]] - `NULL` — это отсутствие значения. И при сортировке с ним нужно быть внимательным.
		- Если ты работаешь в PostgreSQL и хочешь явно управлять положением `NULL`, используй `NULLS FIRST` или `NULLS LAST`.
- [[ORDER BY после WHERE]] - `ORDER BY` выполняется после фильтрации. 
	- Нельзя поставить `ORDER BY` перед `WHERE` или `FROM`. SQL ожидает части запроса в своём порядке.
- [[ORDER BY после GROUP BY]] - `ORDER BY` часто используют вместе с группировкой.
	- [[Можно ли сортировать по колонке, которой нет в SELECT]] - В результате мы выводим только `title`, но сортируем по `rating`. Во многих базах данных это нормальная ситуация.
- [[ORDER BY и UNION]] - Если ты объединяешь результаты через `UNION`, сортировку обычно пишут один раз в самом конце.
- [[ORDER BY по номеру колонки]] - SQL позволяет сортировать по номеру колонки из `SELECT`.
---
- [[GROUP BY и ORDER BY]] - После группировки результат можно отсортировать.
	- Здесь `ORDER BY users_count DESC` сортирует уже готовые группы: сначала страны с большим количеством пользователей, потом с меньшим.
