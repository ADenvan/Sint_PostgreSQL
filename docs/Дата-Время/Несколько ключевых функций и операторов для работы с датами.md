
В PostgreSQL есть несколько ключевых функций и операторов для работы с датами:

1. **`CURRENT_DATE`** — возвращает текущую дату (без времени)
2. **`INTERVAL`** — позволяет вычитать или прибавлять периоды времени
3. **`::date`** — оператор приведения типа, превращает timestamp в дату
^e2
```sql
SELECT 
    client_id,
    SUM(sum_tran) AS spend_30d
FROM transactions
WHERE tran_at::date BETWEEN CURRENT_DATE - INTERVAL '29 days' AND CURRENT_DATE
GROUP BY client_id
ORDER BY spend_30d DESC;
```

^a3be1a

- **`tran_at::date`** — превращает timestamp `2026-04-30 12:00:00+00` в дату `2026-04-30`
- **`CURRENT_DATE - INTERVAL '29 days'`** — вычисляет дату 30 дней назад включая сегодня
    - Если сегодня `2026-05-05`, то 30 дней назад (включая сегодня) = `2026-04-06`
    - Почему 29 дней? Потому что "включая сегодняшний день": 5 мая + 29 дней назад = 30 дней всего
- **`BETWEEN ... AND ...`** — проверяет, что дата попадает в диапазон (включая границы)

## С фиксированной датой:
```sql
SELECT 
    client_id,
    SUM(sum_tran) AS spend_30d
FROM transactions
WHERE tran_at::date BETWEEN DATE '2026-05-05' - INTERVAL '29 days' AND DATE '2026-05-05'
GROUP BY client_id
ORDER BY spend_30d DESC;
```

^8ddb35

Вместо `CURRENT_DATE` мы используем **`DATE '2026-05-05'`** — это явное приведение строки к типу date.

Теперь окно расчета:

- Начало: `2026-05-05 - 29 дней = 2026-04-06`
- Конец: `2026-05-05`
- Итого: 30 дней включая сегодняшний день

## Альтернативный вариант (более явный)
```sql
SELECT 
    client_id,
    SUM(sum_tran) AS spend_30d
FROM transactions
WHERE tran_at::date >= DATE '2026-04-06'
  AND tran_at::date <= DATE '2026-05-05'
GROUP BY client_id
ORDER BY spend_30d DESC;
```
Этот вариант даже лучше для продакшена, потому что:

1. Даты явно видны в коде
2. База может эффективнее использовать индексы по дате
3. Легче отлаживать и понимать временное окно

Оба варианта дадут одинаковый результат. Запускай и проверяй!
