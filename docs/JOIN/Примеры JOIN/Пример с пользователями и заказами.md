
## Пример с пользователями и заказами

Есть таблица `users`:

|id|name|email|
|--:|---|---|
|1|Anna|[anna@example.com](mailto:anna@example.com)|
|2|Boris|[boris@example.com](mailto:boris@example.com)|
|3|Vera|[vera@example.com](mailto:vera@example.com)|
|4|Gleb|[gleb@example.com](mailto:gleb@example.com)|

Есть таблица `orders`:

|id|user_id|amount|created_at|
|--:|--:|--:|---|
|10|1|500|2026-03-01|
|11|1|1500|2026-03-05|
|12|2|200|2026-03-07|
|13|5|3000|2026-03-10|

Нужно получить список заказов вместе с именем покупателя.

```sql
SELECT
  users.name,
  orders.amount,
  orders.created_at
FROM users
INNER JOIN orders
  ON users.id = orders.user_id;
```

Результат:

|name|amount|created_at|
|---|--:|---|
|Anna|500|2026-03-01|
|Anna|1500|2026-03-05|
|Boris|200|2026-03-07|

Что произошло:

- у `Anna` два заказа, поэтому она появилась в результате два раза;
- у `Boris` один заказ, поэтому он появился один раз;
- `Vera` и `Gleb` не попали в результат, потому что у них нет заказов;
- заказ с `user_id = 5` не попал в результат, потому что пользователя с `id = 5` нет в `users`.

Это и есть поведение `INNER JOIN`: показывать только совпавшие пары.
## Как SQL соединяет строки

Возьмём первую строку из `users`:

|id|name|
|--:|---|
|1|Anna|

SQL смотрит в `orders` и ищет строки, где `orders.user_id = 1`.

Находит две строки:

|id|user_id|amount|
|--:|--:|--:|
|10|1|500|
|11|1|1500|

Значит, в результате будет две строки:

|name|amount|
|---|--:|
|Anna|500|
|Anna|1500|

Теперь берём пользователя `Boris` с `id = 2`.

В `orders` есть один заказ с `user_id = 2`, поэтому будет одна строка.

А у `Vera` с `id = 3` заказов нет. Совпадения нет — строки в результате тоже нет.
