
## Условие в ON и условие в WHERE

После `JOIN` всегда есть важная часть — `ON`.

```sql
FROM users u
JOIN orders o
  ON u.id = o.user_id
```

`ON` объясняет базе, как именно связаны таблицы.

Это не просто фильтр. Это правило соединения.

Если написать неправильное условие, результат будет неправильным.

Например, правильно:

```sql
SELECT
  u.name,
  o.amount
FROM users u
JOIN orders o
  ON u.id = o.user_id;
```

А вот так почти наверняка ошибка:

```sql
SELECT
  u.name,
  o.amount
FROM users u
JOIN orders o
  ON u.id = o.id;
```

Почему?

Потому что `u.id` — это идентификатор пользователя, а `o.id` — идентификатор заказа. Они могут случайно совпасть по числам, но логической связи между ними нет.

Правильная связь обычно такая:

> первичный ключ одной таблицы соединяется с внешним ключом другой таблицы.

В нашем случае:

- `users.id` — первичный ключ пользователя;
- `orders.user_id` — внешний ключ на пользователя.
