
- [[Базовый синтаксис]] - В реальном коде чаще пишут просто `JOIN`, потому что короче.
- [[INNER JOIN — это только совпадения]] - Очень важно: `INNER JOIN` не показывает «одинокие» строки.
	- Поэтому `INNER JOIN` удобно использовать, когда тебе нужны только связанные данные.
	- Если нужно показать пользователей даже без заказов, нужен уже не `INNER JOIN`, а `LEFT JOIN`.
- [[Алиасы таблиц]] - В реальных запросах редко пишут полные имена таблиц каждый раз.
- [[Зачем указывать имя таблицы перед колонкой]] - После `JOIN` в результате участвуют колонки сразу из нескольких таблиц. Часто в разных таблицах есть одинаковые названия колонок.
- [[JOIN трёх таблиц]] - `JOIN` можно цеплять один за другим. Таких соединений может быть много. В реальных проектах запросы с несколькими `JOIN` — обычное дело.
	- `users` — пользователи;
	- `orders` — заказы;
	- `products` — товары.
- [[JOIN и WHERE]] - `JOIN` соединяет таблицы. `WHERE` фильтрует результат.
	1. соединить нужные таблицы;
	2. отфильтровать лишние строки;
	3. отсортировать или посчитать агрегаты.
- [[Условие в ON и условие в WHERE]] - `ON` объясняет базе, как именно связаны таблицы.Это не просто фильтр. Это правило соединения.
> первичный ключ одной таблицы соединяется с внешним ключом другой таблицы.
- [[Когда использовать INNER JOIN]] - Используй `INNER JOIN`, когда тебе нужны только строки, у которых есть пара в другой таблице.
- [[Когда INNER JOIN не подходит]] - `INNER JOIN` не подходит, если нужно сохранить строки без пары.
> Покажи всех пользователей, даже если они ничего не заказали.
- Для такой задачи нужен `LEFT JOIN`.
