
# Что такое INNER JOIN в SQL?

INNER JOIN соединяет данные из двух таблиц по общему полю. Самый базовый и самый частый JOIN. Разбираем синтаксис, ON-условие, многотабличные JOIN, частые ошибки и три задачи на тренировку.

`INNER JOIN` — это способ соединить две таблицы по общему полю и оставить только те строки, для которых нашлась пара в обеих таблицах.

Чаще всего слово `INNER` даже не пишут. В SQL обычный `JOIN` почти всегда означает именно `INNER JOIN`.

Представь интернет-магазин. Есть таблица пользователей:

- `users` — кто зарегистрировался на сайте;
- `orders` — какие заказы были оформлены.

В таблице `orders` обычно не хранят имя покупателя. Там хранится только `user_id` — ссылка на пользователя из таблицы `users`.

Почему так? Чтобы не дублировать имя, email и другие данные пользователя в каждом заказе.

Но когда нам нужен отчёт «покупатель — сумма заказа», данные приходится собрать обратно. Вот здесь и нужен `INNER JOIN`.

---
## Зачем нужен JOIN

В хорошей реляционной базе данные обычно разложены по разным таблицам.

Например:

- данные пользователя лежат в `users`;
- заказы лежат в `orders`;
- товары лежат в `products`;
- категории товаров лежат в `categories`;
- платежи лежат в `payments`.

Так база не хранит одно и то же по сто раз.

Если пользователь сделал 20 заказов, его имя не нужно копировать в каждую строку заказа. Достаточно хранить имя один раз в `users`, а в `orders` записывать только `user_id`.

Но в реальных задачах почти всегда нужно смотреть данные вместе:

- имя пользователя и его заказы;
- товар и его категория;
- заказ и статус платежа;
- сотрудник и название отдела;
- книга и имя автора.

Для этого таблицы соединяют через `JOIN`.

## Главное

`INNER JOIN` соединяет две таблицы по общему условию и оставляет только совпавшие строки.

Базовый пример:

```sql
SELECT
  u.name,
  o.amount
FROM users u
JOIN orders o
  ON u.id = o.user_id;
```

Главные правила:

- `INNER JOIN` и просто `JOIN` обычно означают одно и то же.
- Условие соединения пишется после `ON`.
- В результат попадают только строки, у которых есть совпадение в обеих таблицах.
- Если у пользователя нет заказов, `INNER JOIN` его не покажет.
- Если заказ ссылается на несуществующего пользователя, такой заказ тоже не попадёт в результат.
- Алиасы вроде `u` и `o` делают запрос короче и понятнее.
- Если в таблицах есть одинаковые имена колонок, указывай таблицу или алиас.
- Если у одной строки есть несколько совпадений, в результате будет несколько строк.
- Если нужны строки без пары, используй `LEFT JOIN`.
- Если нужны колонки из нескольких связанных таблиц, `JOIN` — основной инструмент.

Если сказать совсем просто: `INNER JOIN` — это способ собрать разложенные по разным таблицам данные обратно в понятную картину, но только там, где между строками действительно есть связь.
