
## Как EXISTS работает логически

Логически запрос можно представить так:

```text
For each customer:
  Check if there is at least one matching order
  If yes, keep this customer
  If no, skip this customer
```

То есть база как будто берёт клиента за клиентом и для каждого задаёт вопрос:

> Есть ли в `orders` строка, где `orders.customer_id = customers.id`?

На практике современные базы данных умеют оптимизировать такие запросы. Они не обязаны буквально выполнять подзапрос заново наивным способом для каждой строки. Оптимизатор может превратить это в более эффективный план, например в semi join.

Но для понимания новичку полезно держать в голове именно такую картину: `EXISTS` проверяет наличие связанных строк для каждой строки внешнего запроса.

## Коррелированный подзапрос

В примере выше внутри подзапроса есть ссылка на внешнюю таблицу:

```sql
WHERE o.customer_id = c.id
```

Здесь `o.customer_id` — колонка из таблицы `orders`, а `c.id` — колонка из внешней таблицы `customers`.

Такой подзапрос называется коррелированным.

Коррелированный подзапрос — это подзапрос, который зависит от текущей строки внешнего запроса.

Пример:

```sql
SELECT *
FROM customers c
WHERE EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.id
);
```

Подзапрос не живёт сам по себе. Для каждого клиента значение `c.id` будет другим:

- для `Anna` это `1`;
- для `Bob` это `2`;
- для `Vera` это `3`;
- для `Gleb` это `4`.

Поэтому проверка каждый раз немного разная.
