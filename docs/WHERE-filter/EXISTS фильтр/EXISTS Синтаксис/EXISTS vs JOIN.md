
## EXISTS vs JOIN

Иногда задачу с `EXISTS` можно решить через `JOIN`.

Например, клиенты с заказами:

```sql
SELECT c.*
FROM customers c
JOIN orders o ON o.customer_id = c.id;
```

Но здесь есть проблема: если у клиента несколько заказов, клиент повторится несколько раз.

Для нашей таблицы результат будет таким:

|id|name|
|--:|---|
|1|Anna|
|1|Anna|
|3|Vera|

`Anna` появилась два раза, потому что у неё два заказа.

Можно добавить `DISTINCT`:

```sql
SELECT DISTINCT c.*
FROM customers c
JOIN orders o ON o.customer_id = c.id;
```

Теперь результат станет правильным:

|id|name|
|--:|---|
|1|Anna|
|3|Vera|

Но запрос стал менее точным по смыслу.

Мы не хотим соединять клиентов с заказами.  
Мы не хотим получать данные заказов.  
Мы не хотим потом убирать дубликаты.

Мы хотим только проверить, что заказ существует.

Поэтому вариант с `EXISTS` читается лучше:

```sql
SELECT *
FROM customers c
WHERE EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.id
);
```

Простое правило:

- нужны данные из обеих таблиц — используйте `JOIN`;
- нужно только проверить наличие связанной строки — часто лучше `EXISTS`.
