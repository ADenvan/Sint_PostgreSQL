
## Главная ловушка NOT IN

Особенно важно быть осторожным с `NOT IN`.

На первый взгляд запрос выглядит нормально:

```sql
SELECT *
FROM customers
WHERE id NOT IN (
  SELECT customer_id
  FROM orders
);
```

Кажется, он должен вернуть клиентов без заказов.

Но если в подзапросе окажется хотя бы один `NULL`, результат может стать неожиданным: запрос может не вернуть ничего.

Почему так происходит?

`NULL` в SQL означает неизвестное значение. А сравнение с неизвестным значением даёт не `TRUE` и не `FALSE`, а `UNKNOWN`.

Допустим, подзапрос вернул такой набор:

```text
1
3
NULL
```

Условие для клиента с `id = 2` превращается в смысл:

```text
2 is not 1
2 is not 3
2 is not unknown
```

Первые две части понятны. А третья неизвестна. SQL не может честно сказать, что `2` точно не равен неизвестному значению. В итоге условие не становится `TRUE`.

Поэтому `NOT IN` с `NULL` в подзапросе — классическая ловушка.

## Почему NOT EXISTS безопаснее

Для поиска строк без связей лучше использовать `NOT EXISTS`.

Так безопаснее:

```sql
SELECT *
FROM customers c
WHERE NOT EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.id
);
```

Здесь `NULL` в `orders.customer_id` не ломает всю проверку.

Почему?

Потому что подзапрос ищет конкретную связь:

```sql
WHERE o.customer_id = c.id
```

Если `o.customer_id` равен `NULL`, он просто не совпадёт с `c.id`.

Такая строка не станет подходящей, но и не испортит результат для всех клиентов.

Практическое правило:

**Для задач вида «найди строки, у которых нет связанной записи» используйте `NOT EXISTS`, а не `NOT IN`.**
