
## Главное 

`IN` с подзапросом проверяет, входит ли значение в список, который вернул другой `SELECT`.

Базовый пример:

```sql
SELECT *
FROM orders
WHERE customer_id IN (
  SELECT id
  FROM customers
  WHERE tier = 'gold'
);
```

Главные правила:

- `IN` означает «значение есть в списке».
- Подзапрос внутри обычного `IN` должен возвращать одну колонку.
- `IN` удобен, когда список значений заранее неизвестен и вычисляется из другой таблицы.
- Дубликаты в подзапросе не меняют результат `IN`.
- `NOT IN` опасен, если подзапрос может вернуть `NULL`.
- Для обратной проверки часто лучше использовать `NOT EXISTS`.
- Если нужно вывести колонки из двух таблиц, чаще нужен `JOIN`, а не `IN`.
- Если подзапрос может вернуть много значений, это нормально, но огромные списки литералов лучше заменять таблицей, массивом или подзапросом.
- `=` подходит для одного значения, `IN` — для списка значений.
- Если нужно сравнить несколько колонок, часто понятнее использовать `EXISTS`.

Если сказать совсем просто: `IN` с подзапросом — это способ сказать базе: «Сначала найди подходящий список значений, а потом оставь только строки, которые в этот список входят».
