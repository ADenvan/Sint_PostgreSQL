
## Важный нюанс с датами и BETWEEN

Если колонка хранит не просто дату, а дату со временем, с верхней границей нужно быть осторожным.

Например, в `created_at` лежат значения такого вида:

|created_at|
|---|
|2024-12-31 10:15:00|
|2024-12-31 23:59:59|
|2025-01-01 00:00:00|

Условие:

```sql
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31'
```

может не захватить весь день `2024-12-31`, если база приводит правую границу к началу дня.

Для дат со временем часто пишут так:

```sql
SELECT id, amount, created_at
FROM orders
WHERE created_at >= '2024-01-01'
  AND created_at < '2025-01-01';
```

Это хороший и безопасный стиль для диапазонов по времени:

- левая граница включается;
- правая граница не включается;
- весь 2024 год попадает в результат.

[[Несколько ключевых функций и операторов для работы с датами]] - 
В PostgreSQL есть несколько ключевых функций и операторов для работы с датами:

1. **`CURRENT_DATE`** — возвращает текущую дату (без времени)
2. **`INTERVAL`** — позволяет вычитать или прибавлять периоды времени
3. **`::date`** — оператор приведения типа, превращает timestamp в дату
