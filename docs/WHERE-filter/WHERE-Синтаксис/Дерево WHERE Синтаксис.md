
- [[WHERE]] - `WHERE` — это фильтр для строк.
	- Когда база видит запрос с `WHERE`, она проверяет условие для каждой строки.
	- Важно: `WHERE` фильтрует **строки**, а `SELECT` выбирает **колонки**.
- [[Операторы сравнения]] - = <> != > < >= <=
- [[AND]] - `AND` означает « `И` ». Для `AND` нужно, чтобы совпало всё.
- [[OR]] - `OR` означает « `ИЛИ` ». `OR` шире, чем `AND`. Он пропускает больше строк.
- [[NOT]] - `NOT` переворачивает условие. Такой запрос удобен, если `in_stock` — булева колонка со значениями `TRUE` или `FALSE`.
- [[Скобки в сложных условиях]] - `()` Когда в одном условии есть и `AND`, и `OR`, лучше ставить скобки.
- [[IN]] - `IN` используют, когда нужно проверить значение по списку вариантов.
- [[NOT IN]] - Есть обратная форма — `NOT IN`. Но с `NOT IN` нужно быть внимательным, если внутри списка или подзапроса может появиться `NULL`.
- [[BETWEEN - значение находится в диапазоне]] - `BETWEEN` проверяет, попадает ли значение в диапазон.
	- [[Важный нюанс с датами и BETWEEN]] - Если колонка хранит не просто дату, а дату со временем, с верхней границей нужно быть осторожным.
	- [[Несколько ключевых функций и операторов для работы с датами]] - 
		- **`CURRENT_DATE`** — возвращает текущую дату (без времени)
		1. **`INTERVAL`** — позволяет вычитать или прибавлять периоды времени
		2. **`::date`** — оператор приведения типа, превращает timestamp в дату
- [[LIKE]] - `LIKE` используют для поиска по тексту, когда нужно не точное совпадение, а шаблон.
	- [[Спецсимволы в LIKE]] - У `LIKE` есть два основных спецсимвола. `%` `_`
	- [[Регистр в LIKE]] - может найти `alice`, но не найти `Alice`.
- [[IS NULL]] - `NULL` в SQL означает не ноль, не пустую строку и не слово `NULL`.  Это отсутствие значения. **для `NULL` нельзя использовать `=` и `<>`. Нужны `IS NULL` и `IS NOT NULL`.**
	- [[Почему NULL так странно себя ведёт]] - Если значение неизвестно, то сравнение тоже становится неизвестным.
