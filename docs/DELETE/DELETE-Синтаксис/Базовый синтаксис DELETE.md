
## Базовый синтаксис DELETE

Самый простой вариант выглядит так:
```sql
DELETE FROM users
WHERE id = 42;
```

Здесь две главные части:
```sql
DELETE FROM users
```

Говорим, из какой таблицы удаляем строки.
```sql
WHERE id = 42
```

Говорим, какие именно строки нужно удалить.

У `DELETE` нет части `SET`, как у `UPDATE`, потому что мы ничего не присваиваем. Мы не меняем колонки, а удаляем строки целиком.
Можно читать запрос почти обычным языком:

> Удали из таблицы `users` строки, у которых `id` равен `42`.

---
## Пример с таблицей пользователей

Пусть есть таблица `users`:

|id|name|email|
|--:|---|---|
|1|Anna|[anna@example.com](mailto:anna@example.com)|
|2|Bob|[bob@example.com](mailto:bob@example.com)|
|3|Vera|[vera@example.com](mailto:vera@example.com)|

Боб попросил удалить аккаунт. Мы знаем, что его `id` равен `2`.

Пишем:
```sql
DELETE FROM users
WHERE id = 2;
```

После выполнения таблица станет такой:

|id|name|email|
|--:|---|---|
|1|Anna|[anna@example.com](mailto:anna@example.com)|
|3|Vera|[vera@example.com](mailto:vera@example.com)|

Строка с `id = 2` исчезла. Остальные строки остались на месте.

Обратите внимание: в таблице теперь нет `id = 2`. И это нормально. Если потом добавить нового пользователя, он обычно получит следующий номер, например `id = 4`, а не снова `2`.

Почему так? Потому что идентификаторы лучше не переиспользовать. Старые логи, заказы, события и внешние системы могли когда-то ссылаться на пользователя с `id = 2`. Если потом выдать этот же `id` другому человеку, начнётся путаница.
