
## Keyset-пагинация: альтернатива большому OFFSET

Для больших таблиц часто используют keyset-пагинацию. Её ещё называют seek pagination.

Идея простая: вместо «пропусти 100000 строк» мы говорим: «дай следующие строки после последнего значения, которое я уже видел».

Например, первая страница:

```sql
SELECT id, name
FROM products
ORDER BY id ASC
LIMIT 20;
```

Допустим, последний товар на странице имеет `id = 120`.

Тогда следующая страница:

```sql
SELECT id, name
FROM products
WHERE id > 120
ORDER BY id ASC
LIMIT 20;
```

Так базе не нужно пропускать огромное количество строк через `OFFSET`. Она может идти дальше от известного ключа.

Для сортировки по дате часто используют пару `created_at` и `id`, чтобы порядок был стабильным.

```sql
SELECT id, title, created_at
FROM posts
WHERE (created_at, id) < ('2026-01-10 12:00:00', 500)
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

Такой подход сложнее, чем обычный `LIMIT OFFSET`, но на больших таблицах часто работает лучше.

Для новичка достаточно понять разницу:

- `OFFSET` удобен и прост для обычных страниц;
- keyset-пагинация лучше подходит для больших лент и глубокого скролла.
