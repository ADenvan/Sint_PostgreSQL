
## NULL: разрешать или запрещать

Каждая колонка либо разрешает `NULL`, либо нет.

Если вы пишете:
```sql
phone TEXT
```
значение можно не указывать, и тогда будет `NULL`.

Если пишете:
```sql
phone TEXT NOT NULL
```
значение обязательно.

`NULL` — это не ноль и не пустая строка. Это «значение отсутствует» или «значение неизвестно».

Иногда `NULL` полезен. Например, у записи может не быть заметки:
```sql
notes TEXT
```

Но если почти все важные поля nullable, схема становится слабой. База перестаёт защищать данные, а код приложения начинает постоянно проверять: «а тут точно что-то есть?»

Хорошее правило:
- если поле обязательно по смыслу — ставьте `NOT NULL`;
- если поле действительно может отсутствовать — разрешайте `NULL`;
- если колонка часто заполнена только для части строк, возможно, стоит подумать об отдельной таблице.

Например, не всегда хорошо делать одну огромную таблицу пользователей с десятками необязательных полей. Иногда лучше вынести дополнительные данные в `user_profiles`, `user_settings` или другую связанную таблицу.
