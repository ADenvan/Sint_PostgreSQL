
## WHERE — самая важная часть UPDATE

`WHERE` отвечает на вопрос:

> Какие строки нужно изменить?

Именно здесь чаще всего происходят дорогие ошибки.

Вот безопасный запрос:
```sql
UPDATE users
SET tier = 'gold'
WHERE id = 1;
```
Он обновит только пользователя с `id = 1`.

А вот опасный запрос:
```sql
UPDATE users
SET tier = 'gold';
```
Здесь нет `WHERE`.

Значит, база обновит **все строки таблицы**.
Если в таблице 3 пользователя — все станут `gold`.  
Если в таблице 3 миллиона пользователей — все 3 миллиона станут `gold`.

База не спросит: «Ты уверен?»  
Она просто выполнит команду.

Поэтому главное правило:
**почти каждый UPDATE должен быть с WHERE.**

Без `WHERE` обновление всех строк тоже иногда нужно, но это уже осознанная массовая операция. Для новичка безопаснее считать, что `WHERE` обязателен.

## Привычка: сначала SELECT, потом UPDATE

Перед тем как менять данные, полезно сначала посмотреть, какие строки попадут под условие.
Допустим, ты хочешь обновить пользователя с `id = 42`.

Сначала проверь:
```sql
SELECT
  id,
  name,
  tier
FROM users
WHERE id = 42;
```
Посмотрел результат. Убедился, что это нужный пользователь.

Только потом запускай:
```sql
UPDATE users
SET tier = 'gold'
WHERE id = 42;
```
Это простая привычка, которая спасает от многих неприятностей.

Особенно на рабочей базе.
Схема такая:
1. Написал `SELECT` с нужным `WHERE`.
2. Проверил строки глазами.
3. Убедился, что всё правильно.
4. Выполнил `UPDATE` с тем же `WHERE`.

Не ленись делать этот шаг. Он занимает несколько секунд, а может сэкономить часы восстановления данных.
