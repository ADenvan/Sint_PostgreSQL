
## SET может использовать старое значение

В `SET` можно не только записывать готовое значение, но и считать новое значение на основе старого.

Например, поднять цену всех товаров на 10%:
```sql
UPDATE products
SET price = price * 1.10;
```
Здесь новое значение `price` считается из старого `price`.

Было `1000`, стало `1100`.  
Было `500`, стало `550`.

Другой пример: начислить пользователю 5 баллов.
```sql
UPDATE users
SET points = points + 5
WHERE id = 42;
```
Это очень важный приём.

Не нужно сначала читать значение в приложении, потом считать новое и записывать обратно. Часто лучше поручить вычисление самой базе.

## Почему арифметику лучше делать прямо в UPDATE

Представь банковский счёт.

Плохой подход в приложении:
1. Прочитали баланс.
2. В коде посчитали новый баланс.
3. Записали новое значение.

Например:
```sql
SELECT balance
FROM accounts
WHERE id = 1;
```

Приложение получило `100`, посчитало `100 - 30 = 70`, потом записало:

```sql
UPDATE accounts
SET balance = 70
WHERE id = 1;
```

Проблема в том, что между чтением и записью мог вмешаться другой процесс. Например, кто-то уже снял деньги или пополнил счёт. Тогда старое значение из приложения может перетереть более свежие данные.

Лучше делать так:
```sql
UPDATE accounts
SET balance = balance - 30
WHERE id = 1 AND balance >= 30;
```

Здесь база сама берёт текущий баланс и уменьшает его на `30` в одной операции.
Дополнительное условие `balance >= 30` защищает от ухода в минус.
Если денег недостаточно, строка просто не обновится.
