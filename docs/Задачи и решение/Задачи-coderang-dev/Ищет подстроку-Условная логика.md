
Нужно добавить к строкам аналитический признак `indicator`: значение `1`, если в `category` встречается подстрока `payment`; значение `2`, если в `category` встречается `transfer`, но при этом нет подстроки `acc`. 
Все остальные категории в результат не включайте. 
Условия проверяйте по порядку: `payment` имеет приоритет — если в `category` есть и `payment`, и `transfer`, строка получает `1`.
^d2
```sql
SELECT client_id, session_id, entered_at, status, category,
    CASE 
        WHEN category LIKE '%payment%' THEN 1
        WHEN category LIKE '%transfer%' AND category NOT LIKE '%acc%' THEN 2
    END AS indicator
FROM otp_codes
WHERE category LIKE '%payment%' 
   OR (category LIKE '%transfer%' AND category NOT LIKE '%acc%')
ORDER BY entered_at;
```

^c29dad

### 🛠 Ключевые инструменты:
- **`LIKE '%payment%'`** — ищет подстроку `payment` в любом месте строки. Символы `%` означают "любые символы до и после".
- **`CASE WHEN ... THEN ... END`** — условная логика. Проверяет условия по порядку и возвращает первое совпавшее значение.
### 🧠 Разбор по шагам:
1. **`WHERE` (фильтрация строк):**
    - `category LIKE '%payment%'` — оставляем строки, где есть `payment`
    - `OR (category LIKE '%transfer%' AND category NOT LIKE '%acc%')` — ИЛИ строки, где есть `transfer`, но нет `acc`
    - Строки типа `otp-card`, `otp-login`, `otp-2fa-acc` отсекаются
2. **`CASE` (создание колонки indicator):**
    - Сначала проверяем `payment` → если есть, ставим `1` (приоритет!)
    - Потом проверяем `transfer` без `acc` → ставим `2`
    - Если ни одно условие не сработало, будет `NULL` (но это невозможно, т.к. мы уже отфильтровали в `WHERE`)
3. **Почему условия в `WHERE` и `CASE` дублируются?** Это важно! `WHERE` фильтрует строки ДО их попадания в результат. `CASE` вычисляет значение для каждой строки. Если не продублировать условия в `WHERE`, ты получишь все строки, но с `NULL` в `indicator` для неподходящих.
