
В мини-проекте Яндекс Практикума по магазину канцелярии нужно определить ценовую категорию каждого купленного товара. 
По каждому заказу подтяните цену товара из `prices` и категорию из `categories`, в чей интервал `price_range` попадает эта цена.
Важное ограничение: не используйте `CASE` и `IF`; категория должна определяться только через соединение таблиц по интервалу цены. 

^a22
```sql
SELECT  
    o.last_name, 
    o.product, 
    p.price, 
    c.category
FROM orders o
JOIN prices p ON o.product = p.product
JOIN categories c ON p.price <@ c.price_range::numrange;
```

^b6a7ba

### 🧠 Разбор "магии" по шагам:

1. **Цепочка JOIN-ов (Поезд)**: Мы начинаем с `orders` (локомотив). Прицепляем `prices` по совпадению названия товара (`ON o.product = p.product`). И к этому результату прицепляем `categories` по новому, хитрому условию.
2. **`c.price_range::numrange`**: В таблице `categories` колонка `price_range` хранится как обычный текст (строка), например: `'[0,500)'`. С помощью `::numrange` мы говорим PostgreSQL: _"Преобразуй эту строку в настоящий математический числовой диапазон"_. Теперь база понимает, что это интервал от 0 (включительно, круглая скобка) до 500 (исключительно, квадратная скобка).
3. **Оператор `<@` (is contained by)**: Это специальный оператор PostgreSQL для диапазонов. Он читается как _"содержится в"_. Условие `p.price <@ c.price_range::numrange` означает: _"Возьми цену товара и проверь, попадает ли она внутрь этого математического диапазона"_.
    - Например: `120.00 <@ '[0,500)'` → **TRUE** (попадает в cheap).
    - Например: `3500.00 <@ '[500,5000)'` → **TRUE** (попадает в medium).^4169ae
### 💡 Почему это круче, чем `CASE` или `BETWEEN`?

- **Читаемость:** Одна строчка вместо 4-5 строк `WHEN ... THEN ...`.
- **Производительность:** PostgreSQL умеет строить специальные индексы (GiST) для диапазонов, что делает поиск по интервалам молниеносным на миллионах строк.
- **Точность:** Запись `[0,500)` (круглая скобка) математически корректно обрабатывает границы. Если цена ровно 500, она не попадет в `cheap`, а попадет в `medium` `[500,5000)`, что полностью соответствует логике интервалов.
