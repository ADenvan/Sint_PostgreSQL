
Банк «Открытие» анализирует сценарии двухфакторной авторизации и хочет понять, где клиенты чаще всего вводят OTP-код. 
Это поможет улучшить UX и оценить нагрузку на SMS-шлюз. 
Найдите категорию с наибольшим числом попыток ввода кода. 
Учитывайте все попытки независимо от `status`.

- ### 🧠 В чем суть задачи (простыми словами):
Представь, что ты сидишь перед таблицой со всеми попытками ввода кодов. Тебе нужно:
1. **Посчитать**, сколько всего попыток было в каждой категории (`payment`, `login`, `transfer` и т.д.).
2. **Сравнить** эти числа между собой.
3. **Назвать ту категорию, где число попыток МАКСИМАЛЬНОЕ**.

То есть база данных должна **САМА найти** ответ, а не ты за нее.
```sql
SELECT category, COUNT(category) AS codes_count
FROM otp_codes
WHERE category = 'payment'
GROUP BY category

SELECT category, COUNT(*) AS codes_count
FROM otp_codes
GROUP BY category
ORDER BY codes_count DESC
LIMIT 1;
```

### 🧠 Разбор по шагам (как база сама находит ответ):

1. **`GROUP BY category`** — база раскладывает все строки по "коробочкам" с надписями `payment`, `login`, `transfer`.
2. **`COUNT(*) AS codes_count`** — внутри каждой коробочки она считает количество строк (попыток). Получается что-то вроде:
    - `payment` → 6
    - `login` → 4
    - `transfer` → 4
3. **`ORDER BY codes_count DESC`** — база **сортирует** коробочки по убыванию количества. Самая "толстая" коробочка оказывается на самом верху.
4. **`LIMIT 1`** — это финальный штрих. Он говорит базе: _"Мне нужна только **первая** строка из отсортированного списка"_. То есть та категория, где попыток больше всего.
